# 📖 get_next_line - ファイルからの1行読み込み関数

> 指定されたファイルディスクリプタから、呼び出すたびに「次の1行」を正確に読み取る関数を実装するプロジェクトです。

一度にすべてのデータを読み込むのではなく、必要な分だけを読み取る効率的なメモリ管理と、読み込みすぎたデータを次回のために保持しておく **「静的変数（static）」の活用** がこの課題の核心です。



## 🎯 技術的な達成目標
- [ ] **データの永続化**: `static` 変数を用い、関数の実行が終わっても読みかけのデータをメモリ上に保持する仕組み。
- [ ] **バッファ管理**: コンパイル時に指定される `BUFFER_SIZE` の大きさに左右されず、正確に改行までを切り出すロジック。
- [ ] **メモリの安全な取り扱い**: 文字列の結合や切り出しの過程で発生する、動的メモリ（malloc）の確保と解放の徹底。
- [ ] **複数ファイルの並行読み込み (Bonus)**: 配列形式の `static` 変数を用い、異なるファイルディスクリプタの状態を個別に保持する機能。

## 📝 実装上のエピソード 1：ダブルポインタによる状態の同期
読みかけのデータを保持する `static char *rem` を、別のサブ関数（`read_manage_rem` など）から直接更新するために、ポインタのポインタ（`char **`）を使用して実装しました。
サブ関数内で `free` と再割り当てを行った結果を、確実に本体の変数へ反映させる必要があり、メモリのアドレスが今どこを指しているのかを常に意識する「ポインタ操作」の基礎が叩き込まれました。

## 📝 実装上のエピソード 2：極端な BUFFER_SIZE への対応
`BUFFER_SIZE` が `1` のような極端に小さい場合や、逆に非常に大きい場合でも、メモリリークを起こさず正確に行を切り出す堅牢性を追求しました。
特に、読み込みループ（`while`）の中で改行コードを検知した瞬間に、余ったデータをどう保存し、どこで `free` するかという境界条件の処理を一つずつ潰していくことで、予期せぬ入力に対しても壊れないプログラムの書き方を学びました。

## 🏃‍♂️ 実行方法
本プロジェクトは、コンパイル時にバッファサイズを自由に指定してテストすることが可能です。

# BUFFER_SIZEを指定してコンパイル
cc -Wall -Wextra -Werror -D BUFFER_SIZE=32 get_next_line.c get_next_line_utils.c main.c
