# 📈 push_swap - 2つのスタックを用いた効率的なソートアルゴリズムの実装

> 2つのスタック（Stack A/B）と限られた命令のみを使用し、最小限のステップ数で数値を整列させるプロジェクトです。

本プロジェクトでは、データ構造として**循環二方向連結リスト**を採用し、計算量を抑えるための**座標圧縮**や、移動コストを計算して最適解を選択する **Turk Algorithm** を実装しました。

## 🎯 技術的な達成目標

* **高度なデータ構造の管理**: ポインタを駆使した循環二方向連結リストの実装と、スタック操作（swap, push, rotate）の構築。
* **効率的なソートロジック**: 数値をインデックス化する座標圧縮によるアルゴリズムの簡略化。
* **コスト計算に基づく最適化**: 各要素をStack Bへ送る際の最短手数を算出する Turk Algorithm の実装。
* **厳格なエラーハンドリング**: 整数範囲のチェック、重複の検知、不正な入力に対する堅牢なバリデーション。

## 🛠️ 技術スタック

* **言語**: C言語 (C99)
* **データ構造**: 循環二方向連結リスト (Circular Doubly Linked List)
* **アルゴリズム**: Turk Algorithm
* **ビルドツール**: Makefile (`-Wall -Wextra -Werror` 対応)

## 💡 実装の詳細と学習成果

### 1. 循環二方向連結リストによるスタックの実装
スタックの先頭（head）と末尾（bottom）が繋がった循環構造を採用しました。
* **実装**: 各ノードが `next` と `prev` の両方のポインタを持ち、Stack A/B を跨いで移動する `push` や、要素を回転させる `rotate` を、ポインタの繋ぎ変えのみで定数時間 $O(1)$ で実行できるようにしました。
* **成果**: メモリ上のデータがどのようにリンクされ、ポインタ一つで構造全体がどう変わるかを物理的に理解しました。

### 2. 座標圧縮（インデックス化）による前処理
入力された巨大な数値や負の数を、その大小関係を維持したまま `0` から `n-1` の連番に変換しました。
* **実装**: 予備の配列で一度ソート（`simple_sort`）を行い、元の数値が何番目かを特定して書き換えるロジックを実装しました。
* **成果**: アルゴリズムが扱うデータを「値そのもの」ではなく「順位」に抽象化することで、比較処理やロジックの簡略化が可能になることを学びました。

### 3. コスト計算に基づく最適化 (Turk Algorithm)
Stack A から B へ要素を移す際、どの要素を動かすのが最も手数が少ないかを毎ステップ計算しています。
* **実装**: `ra+rb`, `rra+rrb`, `ra+rrb`, `rra+rb` という4つの回転パターンをすべてシミュレーションし、最小コストの移動を選択します。
* **成果**: 単純なルールの積み重ねではなく、計算結果に基づいて「最善の戦略」を動的に選択するアルゴリズムの設計能力が身に付きました。

## 📝 実装上のエピソード

### 1. 循環リストにおける「Push」の繋ぎ変えの難しさ
要素を Stack A から B へ移動させる際、単に先頭を外すだけでなく、残された A の末尾と新しい先頭を繋ぎ直し、さらに受け入れ側の B でも末尾と新しい先頭を繋ぎ直す必要があります。
特にスタックのサイズが 0 や 1 になる際の境界条件でポインタが迷子になりやすく、図を書いてポインタの全パターンを整理することで、セグメンテーションフォルトのない堅牢な処理を完成させました。

### 2. 共通の回転（rr / rrr）を活かした手数削減
Turk Algorithm の核は、A と B のスタックを同じ方向に回転させる際、`ra` と `rb` を個別に呼ぶのではなく、`rr` を使って同時に動かすことで手数を節約することです。
この「共通の動きを一つにまとめる」ための条件分岐を実装したことで、大きなデータセットに対しても非常に少ない手数でソートを完了させることが可能になりました。
