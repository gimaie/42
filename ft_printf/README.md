🖋️ ft_printf - 可変長引数処理と書式指定子の再実装
標準関数 printf の挙動を再現するプロジェクトです。

スタックメモリ上に配置された不定数の引数を、書式指定子に基づいた適切な型で取得し、文字列変換を経て標準出力へ書き出す一連の処理を構築しました。

🎯 技術的な達成目標
可変長引数 (Variadic Arguments) の制御: va_list を用いたスタック上の引数ポインタの走査。

書式指定子のパースとディスパッチ: % に続く文字を解析し、適切な変換関数へ分岐させるロジックの実装。

基数変換アルゴリズムの自作: 10進数、16進数、およびポインタアドレス用の文字列変換処理の構築。

正確な出力バイト数のカウント: すべての write 実行結果を累積し、最終的な出力合計値を算出する設計。

🛠️ 技術スタック
言語: C言語 (C99)

主要コンポーネント:

<unistd.h>: write システムコールによる出力。

<stdarg.h>: va_start, va_arg, va_end マクロによる引数操作。

ビルドツール: Makefile (-Wall -Wextra -Werror 対応)。

💡 実装の詳細と学習成果
1. 引数ポインタの逐次処理
va_list を用いて、メモリ上に連続して配置された引数リストを走査しています。

実装: deal_per 関数内で指定子（c, s, p, d, i, u, x, X）を判定し、va_arg を通じてスタックから要求されたバイト数分だけデータを取り出します。

成果: 関数の引数がスタックメモリにどのように配置され、型サイズに基づいたオフセットがどのように計算されるかという物理的な動作を習得しました。

2. 基数変換とポインタの可視化
%p や %x 等の出力を実現するため、数値を直接文字へ変換する関数群を実装しました。

実装: unsigned long 型のアドレス値を16進数文字列に変換する ft_itoa_ptr を自作しました。ポインタ出力時は、リテラル "0x" を write した後に変換後の文字列を出力する多段的な処理を行っています。

成果: 64bit環境におけるポインタサイズと unsigned long の整合性、およびメモリアドレスという生データを文字列へ変換する際の手順を習得しました。

3. 動的メモリ管理の徹底
数値変換の過程で malloc を使用する際、メモリリークを確実に防止する構造を構築しました。

実装: print_dec や print_hex 等の関数内で、一時的に確保した文字列を write した後、即座に free を実行して領域を解放しています。

成果: 短期間の「確保・使用・解放」のサイクルを関数単位で完結させることで、リソース管理の堅牢性を高めました。

📝 実装上のエピソード：エラー伝播と累積カウントの整合性
ft_printf の実装で最も注意を払ったのは、「エラー発生時の安全な終了と適切な戻り値」です。

printf の仕様では、出力した全バイト数を返す必要がありますが、単純に n += deal_per(...) と累積させると、deal_per 内の write が失敗して -1 を返した場合、累積値 n が単に 1 減るだけで、関数全体としてエラー（-1）を返せなくなります。

これを解決するため、ループ内での戻り値を毎回検証し、負の値が返された瞬間に処理を中断して即座に -1 を確定させるロジックを構築しました。
「正常系のカウント」と「異常系の検知」を両立させるこの実装を通じて、単なる計算処理ではない、システムコールレベルのエラーハンドリングの重要性を学びました。
