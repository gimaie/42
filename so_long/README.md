# 🛠️ pipex - システムコールを用いたプロセス間のデータ連携

`pipe` や `fork` といったシステムコールを活用し、複数のプログラム間でデータをやり取りする仕組みを構築するプロジェクトです。

本プロジェクトでは、標準入出力の切り替えや、プログラム（プロセス）の実行管理を、C言語の基本的な関数を組み合わせて実装しました。普段シェルが自動で行っている処理を、自分の手で一つずつ制御する経験を積むことが目的です。

## 🎯 技術的な達成目標
* **プロセスの実行制御**: `fork` でプログラムのコピーを作成し、`waitpid` でその終了を待機する一連の流れの管理。
* **入出力のリダイレクト**: `dup2` を使い、ファイルやパイプを標準的な入出力先（`0`番や`1`番）として設定する処理。
* **コマンドの探索**: 環境変数 `PATH` を解析して、指定されたコマンドの実行バイナリがシステムのどこにあるかを特定するロジックの実装。

## 📝 実装上のエピソード 1：配管工事のようなファイルディスクリプタ管理
一番の難所は、`pipe` で作ったデータの通り道を、`dup2` と `close` を使って正しく繋ぎ変える作業でした。
どの番号（ファイルディスクリプタ）がどこに繋がっているのか、どのタイミングで閉じないとデータが止まってしまうのか。この「データの通り道」を物理的に管理する感覚を養うことで、プログラムが外部（ファイルや他のプログラム）と通信する際の基礎的な作法を学びました。

## 📝 実装上のエピソード 2：execve 実行前後のリソース管理
`execve` は成功すると現在のプログラムを新しいプログラムで完全に書き換えてしまうため、その直前までにすべてのメモリ解放やファイルディスクリプタの整理を終えておく必要があります。
「成功した瞬間に自分の書いたコードは消えるが、失敗した時だけエラー処理へ進む」という `execve` 特有の挙動を前提に、どのタイミングでリソースを片付けるべきか、その境界線の設計を徹底しました。
