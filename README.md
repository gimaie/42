# 🚀 42 Tokyo

> 42 Tokyoでのプロジェクトを通じて、標準ライブラリに頼らず、システムコール（OSへの命令）などの最小限の道具からプログラムを構築した記録です。

---

## 💡 取り組みの背景と環境

### 1. 便利な関数を使わずに「裏側」を自作する
42では、普段当たり前に使われている便利な関数の多くが使用禁止されています。
そのため、メモリの確保・解放の管理はもちろん、連結リストやスタックといったデータ構造も、課題ごとにゼロから自分の手で実装する必要がありました。
「何が起きているのか」を自分のコードで一行ずつ確認しながら進める必要があり、手間はかかりますが、プログラムが動く土台の部分を直接操作する経験を積みました。

### 2. 教科書のない中での実装
この学習環境には先生も教科書も存在せず、提示されるのは課題（仕様書）のみです。
「正解」が用意されていない状況で、公式の技術ドキュメントを読み込み、実際にコードを書いては壊す作業を繰り返すことで、一つ一つの課題を形にしてきました。
わからないことに直面した際、仕様を調べ、自分の手で検証して進めるというプロセスを全てのプロジェクトで共通して行っています。

## 📂 プロジェクト一覧

各プロジェクト名から詳細な技術解説（個別のREADME）を確認できます。

| プロジェクト名 | 概要 | 扱った主な仕組み |
| :--- | :--- | :--- |
| **[libft](./libft)** | 標準関数の再実装 | ポインタ操作、動的メモリ管理 |
| **[ft_printf](./ft_printf)** | 出力関数の自作 | 可変長引数、型に応じたデータ変換 |
| **[get_next_line](./get_next_line)** | 1行読み込み関数 | static変数によるデータの保持 |
| **[pipex](./pipex)** | UNIXパイプの再現 | プロセスの複製（fork）、入出力の繋ぎ変え |
| **[so_long](./so_long)** | 2Dゲーム開発 | 再帰による経路探索、イベント制御 |
| **[push_swap](./push_swap)** | 効率的なソート | 循環二方向連結リスト、コスト計算による最適化 |
